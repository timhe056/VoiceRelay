## 1. 延迟分析：Host 中继 vs 专用服务器

### 1.1 当前模型（Host 中继）

```
玩家A ──UDP──→ Host（玩家C的机器）──UDP──→ 玩家B
```

端到端延迟 = A→Host RTT/2 + Host→B RTT/2 + Host 转发处理耗时

| 场景 | A→Host | Host→B | 总延迟 |
|------|--------|--------|--------|
| 三人同城、Host 有线 | 5ms | 5ms | ~10ms |
| Host 同城、B 异地 | 5ms | 30ms | ~35ms |
| Host WiFi 差 | 15ms + jitter | 15ms + jitter | ~30ms + 高抖动 |
| Host 4G 热点 | 40ms + 高丢包 | 40ms + 高丢包 | ~80ms + 高丢包 |

**核心问题不是跳数（始终 2 跳），而是 Host 网络质量的不可控。**

### 1.2 专用语音服务器模型

```
玩家A ──UDP──→ 语音服务器（数据中心）──UDP──→ 玩家B
```

| 场景 | A→服务器 | 服务器→B | 总延迟 |
|------|---------|---------|--------|
| 同区域，服务器 BGP 机房 | 5-10ms | 5-10ms | **10-20ms** |
| 跨区域，服务器居中 | 20ms | 20ms | **~40ms** |
| 海外玩家（服务器在境内） | 60ms | 60ms | **~120ms** |

### 1.3 延迟结论

| | Host 中继 | 专用语音服务器 |
|---|----------|--------------|
| 理想情况（Host 网络好） | 10ms | 10-20ms（略差） |
| 一般情况（Host WiFi） | 30ms + 抖动 | 10-20ms（**显著改善**） |
| 恶劣情况（Host 移动网络） | 80ms + 高丢包 | 10-20ms（**质变**） |
| 延迟一致性 | 取决于房主 | **稳定、可预测** |

**专用服务器不一定降低最低延迟，但大幅提升了延迟的一致性和可靠性。额外收益：**

1. Host 断线语音不中断
2. Host 带宽解放（不再承担 N×N 语音转发）
3. 服务端可控：丢包检测、自适应码率、优先队列

## 2. 框架方案对比（2026-05 评估）

| | **自研 UDP Relay** | **Steam Voice** | **LiveKit** | **Mumble/Murmur** | **mediasoup** |
|---|---|---|---|---|---|
| **协议** | Raw UDP + 自定义帧 | Opus over Steam | WebRTC SFU | Raw UDP + TCP 控制 | WebRTC SFU |
| **Godot C# 客户端** | ✅ 自主 | ✅ SteamNetGodot | ⚠️ GDScript only | ❌ lib 未维护 | ❌ 无方案 |
| **部署复杂度** | ★★☆ | ☆☆☆ | ★★★ | ★☆☆ | ★★★★★ |
| **延迟（口到耳）** | 5-15ms | 15-150ms | 80-150ms | 10-30ms | 70-100ms |
| **认证** | 自定义 | Steam ID | JWT | 自有（弱） | 无 |
| **适合本项目** | ✅✅✅ | ✅✅ (Steam限定) | ✅ (有坑) | ❌ | ❌ |

**选定自研 UDP Relay**，原因：
- 延迟最优（纯 UDP，无 WebRTC 协议栈开销）
- 完全可控（编码、转发、监控全白盒）
- 不锁定任何平台
- 最终实现：Go 独立服务（详见 tech_selection.md 和 README.md）
